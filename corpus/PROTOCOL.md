# Structured public-fix screen

This is a post-discovery, structured evidence ledger rather than a systematic
literature review or preregistered mining study. Candidate leads came from the
project brief, cited reports, and GitHub commit searches for gettext/ngettext,
placeholder, plural, KeyError, and formatting repairs. The screen freezes one
row per candidate and one `repair_group` per underlying maintenance change.
Forks, distribution aggregates, submodule pointers, companion catalog commits,
and locale copies are not separate defects.

A historical case is counted only when the artifact retains a versioned
application boundary, an independently justified technical obligation, and an
executable before/after replay. A commit description without its failing input
is `screened-not-counted`. Tool changes, tests, type stubs, and discussions are
kept as prior art or exclusions. `ordinary_1_2_detects` and
`guard_product_needed` are populated only for executed replays; null is not a
measured miss. No maintainer was contacted, and the classifications are author
analysis rather than independent human annotation.
