# MsgBranch investigation protocol

Protocol date: 2026-09-30. Discovery metadata had been inspected before the first measurements. Later evidence additions are identified by their freeze conditions and immutable source identifiers rather than by manuscript-version labels.

## Eligibility and units

A case requires public versioned source, a lawful retrieval route, an application or test localization call, and a technical obligation independent of MsgBranch. Python gettext/Babel and Jinja integrations are primary; Fluent cases use the pinned upstream runtime. Forks, translated copies, companion catalog commits, and multi-repository propagation of one repair are deduplicated. Test-only and preventive changes are classified separately from executable historical repairs.

The units are kept distinct:

- a historical repair is one underlying maintenance change;
- a project finding is one `(call site, catalog)` qualification record;
- a generated mutant is a sensitivity instrument;
- a runtime observation is an execution, not a defect;
- a holdout boundary is an adapted public call/catalog pair selected after analyzer freeze.

No production service, private evidence, prose-quality judgment, or human translation assessment is used.

## Discovery and evidence admission

Initial discovery candidates included Sphinx issue 7282 and repair `6682f898...`, Kiwi `c4c37fe...`, Miro `93d3423...`, and SecureDrop `45e9b38...`. The frozen public screen now contains 20 leads collapsed to 17 repair groups. Four satisfy the executable-repair rule: Sphinx, OpenHangar, xrpldashboard, and AZM CRM. Development-stage observations, preventive fixes, duplicates, and unreplayed leads remain recorded but do not enter the historical-repair denominator.

Before broad evaluation, each admitted repair must expose a local executable boundary, an ordinary same-oracle regression, and a repair-derived assertion or documented runtime contract. Readable fallback is not classified as failure unless the application obligation requires catalog resolution. Reconstructing a boundary is reported as such and is not presented as full-application execution.

## Baselines and controls

Baselines are matched to their supported formats and evidence layers:

- Babel catalog checkers and the actual `pybabel compile --use-fuzzy` command;
- Python `gettext`/`GNUTranslations` native execution;
- artifact existence plus a known-message runtime smoke lookup;
- placeholder-set and format-kind checks;
- ordinary counts `1,2` and the disclosed seven-count set;
- direct attached-syntax qualification;
- bounded flow qualification;
- source-only, locale-only, equal-budget, and random witness selection;
- retained Weblate 5.13 Python-format/brace-format components;
- retained LocalHero placeholder/check components;
- the pinned python-fluent runtime and disclosed observer.

GNU `msgfmt`, a configured full Weblate deployment, the complete LocalHero CLI, and complete upstream application suites are unavailable as complete runs and receive no miss count.

Constructed controls cover named reordering, legal branch-specific omission, contexts, one-form and six-form locales, empty/missing translation with explicit fallback policy, nested brace fields, percent characters, wrong keys, wrong types, count-conditioned suppliers, deferred formatting, and dynamic unknowns. Raw outputs retain selected branch, resolution origin, supplier shape, required names/types, exceptions, and covered counts.

## Boundary and project qualification

A boundary record contains source, catalogs, locale configuration, runtime profile, input domain, wrapper binding, and acceptance obligation. Catalogs are compiled to MO with Babel and loaded through `GNUTranslations`. The selected runtime pattern is checked only against the supplier shape recovered for that call and count region; arguments are never synthesized from catalog placeholders.

The project analyzer never imports the target. `direct` mode recognizes suppliers attached syntactically to a literal translation call. `flow` mode performs bounded intraprocedural def-use recovery for local aliases, later percent/brace formatting, literal mappings and sequences, keyword suppliers, primitive types, contexts, and count-conditioned assignments. Unsupported calls, arbitrary container mutation, reflection, interprocedural injection, path uncertainty, and budget exhaustion remain `unknown`.

The trusted analyzer suite has 26 controls. Its expected project statuses distinguish the interpreter's two unsupported inputs from the additional static character-range uncertainty; bounded native execution of that character case is still valid. Its classification is compared with 4,623 direct runtime executions over the declared domains. The same 48 findings from 26 controls and six field slices are then classified by both direct and flow modes. The ablation reports status changes on identical findings, not extra projects or defect counts.

## Guard-product studies and costs

The optional planner covers `message(n)` over bounded integer domains using admitted threshold and residue predicates. Validation seed 260930 and confirmation seed 261001 each generate 96 clean/mutant pairs across 12 locale rules. Both studies retain all active and inactive mutations, source/generator hashes, raw outcomes, planner receipts, and selected witnesses. Direct native execution determines mutation activation independently of witness selection.

Each comparator uses the same native oracle. Equal-budget random selection uses 100 deterministic trials per family. Cell evaluation, coalesced boundary interpretation, and final replay are counted separately. The cost study uses four generated boundaries, domains of 201, 1,001, and 10,001, and five warmed repetitions with rotated order. Product planning, exhaustive-adapter interpretation, and direct native enumeration are timed separately. No artificial route latency or production speedup is introduced.

## Application controls and tool components

Jupyter Server 2.17.0 is a neutral gettext control selected after adapter design; its complete Chinese PO and exact method slice are retained, but locale loading and server execution are bypassed. Bedrock contributes seven upstream Fluent expected outputs with five byte-verified FTL fixtures; its local loader/settings shim is explicit. OpenHangar preserves two Jinja call expressions and the affected French/Dutch entry. xrpldashboard preserves the changed Jinja expression. AZM CRM preserves one exact message pair to isolate missing-MO delivery. Each provenance record identifies transformations and licenses.

The complete Babel CLI is executed on 228 retained PO catalogs and two negative controls. Its MO bytes and loaded catalogs are compared with the pinned in-process writer. Weblate and LocalHero are fixed source components under disclosed fixture harnesses; their catalog-policy diagnostics remain separate from caller-failure detection.

## Retained external-project regressions

Before selecting holdout projects, SHA-256 hashes were recorded for `project.py`, `runtime.py`, `program.py`, and `partition.py`. Solaar and virt-manager were then admitted at immutable commits. Each retains one bounded call boundary, exact relevant catalog entries, provenance, transformation notes, and GPL text. The default check evaluates the retained regression contracts and native agreement on these boundaries. It does not estimate whole-project recall, defect prevalence, or linguistic quality. `scripts/holdout_evaluate.py --mode frozen-source` fails if analyzer hashes differ from `data/holdout/PROTOCOL.json`.

## Measures and reporting

Report historical repairs, project findings, controls, mutants, runtime executions, reachable branch identities, selected witnesses, unknowns, costs, cache counts, and source-component diagnostics in separate denominators. Generated-study paired statistics describe the retained constructed families only. Microbenchmark timings are environment-specific. Project scaling measures parsing, Babel compilation, AST scanning, runtime selection, and qualification on generated fixtures at 1, 25, 100, and 400 calls.

Every headline number must be derivable from retained machine-readable results. `scripts/audit_results.py` independently recounts raw/selected consistency, baseline labels, project ablation, holdout freeze, Babel CLI outcomes, tool-component records, and cost medians. Claims do not include linguistic correctness, usability, accessibility, industrial deployment, maintenance hours, or guaranteed acceptance.
